# Правила DJMetry

Единственный документ с правилами проекта. Новые правила добавляются сюда, отдельных документов с правилами не заводим.
Справочники: [BACKEND_API.md](BACKEND_API.md) — контракт с бэкендом, [DJMETRY_SERVICE_OVERVIEW.md](DJMETRY_SERVICE_OVERVIEW.md) — что есть на сайте.

## 1. Как идёт работа над задачей

1. **Задача сразу записывается** в [журнал задач](#8-журнал-задач) внизу этого документа: дата, суть, тип (**Фронт** или **Бэкенд**), статус.
2. **Тип определяет приоритет:**
   - **Фронт** (мобильное / десктоп-приложение, UI): приоритет — API бэкенда. Контракт задаёт бэкенд, фронт под него подстраивается.
   - **Бэкенд**: приоритет — бэкенд. Фронт ждёт и потом подстраивается под новый контракт.
3. Для экрана — макеты на выбор, каждый сразу на телефоне, планшете и десктопе ([раздел 3](#3-каждый-экран--для-всех-устройств)).
4. Реализация одним общим кодом + тесты в том же изменении ([раздел 4](#4-тесты)).
5. Проверка на устройствах, запись результата в журнал.
6. **Язык — всегда русский**: ответы в чате, документация, журнал, комментарии в коде, сообщения коммитов.

## 2. Фронт отрисовывает, бэкенд считает

- **Все вычисления — на бэкенде:** DJMetry Score, позиции и тренды, лимиты подписок и голосов, статусы и оплата букинга,
  налоги, верификация. Фронт показывает то, что пришло, и не дублирует бизнес-логику.
- Проверки на фронте — только для удобства (не отправить заведомо пустое), окончательное решение и текст ошибки — от бэкенда.
- **Нужных данных нет в API — фронт не придумывает их сам,** а заводит задачу для бэкенда в журнале (тип «Бэкенд»)
  и на время показывает заглушку «скоро».
- Контракт (эндпоинты, поля, ошибки) описывается в [BACKEND_API.md](BACKEND_API.md). Расхождение документации и прода
  фиксируется там же и тестом на реальный ответ (`ProdPayloadsTest`).

## 3. Каждый экран — для всех устройств

Экран с первого дня делается для телефона, планшета и десктопа — одним общим Compose-экраном в `shared`.
Экран без одной из раскладок не считается готовым.

| Ширина окна | Класс | Где встречается | Раскладка |
|---|---|---|---|
| < 600 dp | `Compact` | телефоны, iPad Split View, узкое окно | один столбец, парящий таббар снизу |
| 600–839 dp | `Medium` | iPad портрет, среднее окно | навигация слева, контент + панели под ним |
| ≥ 840 dp | `Expanded` | iPad альбом, десктоп | навигация слева, контент по центру, панель справа |

- Раскладка — по ширине окна, не по типу устройства. Код: `ui/layout/Adaptive.kt`, тесты — `AdaptiveLayoutTest`.
- Телефоны — только портрет; планшеты и десктоп — любая ориентация (iOS `UISupportedInterfaceOrientations_iPhone`,
  Android `MainActivity` по `smallestScreenWidthDp`).
- Навигация: телефон — парящий таббар снизу с `#` в центре; планшет и десктоп — та же «таблетка» вертикально слева.
- Контент не растягивается: `widthIn(max = …)`, свободное место — второй панели.
- Клавиатура (планшет, десктоп): основные действия дублируются клавишами (стрелки в колоде).
- Размеры в dp/sp, однострочные подписи с многоточием, крупный системный шрифт не ломает экран.
- Загрузка — скелетон той же формы, что готовый экран (`ui/components/Skeleton.kt`), не крутилка; крутилка только на кнопке с действием.
- Бейджи и счётчики — только `PillBadge` / `CountBadge` (центр по цифрам, не по рамке строки — на iOS рамка смещена).
- Текст в ограниченном месте (плитки, кнопки, кольца, бейджи) — `AutoSizeText`; проверка при системном шрифте ×1.3 (`BigFontFitTest`).

### Готово = идеально на всех устройствах
Мы пишем под **все** устройства: телефоны, планшеты, десктоп. Экран не готов, пока он не проверен на всей матрице:

| Устройство | Окно, dp | Что проверяем |
|---|---|---|
| iPhone SE (самый узкий) | 375 × 667 | ничего не обрезано, длинные имена и переводы помещаются |
| Обычный телефон | 393 × 852 | основной сценарий |
| iPad портрет | 820 × 1180 | `Medium`: навигация слева, две колонки |
| iPad альбом | 1180 × 820 | `Expanded`: раскладка десктопа |
| Десктоп | 1440–1600 × 900–1000 | окно можно сужать до телефона и расширять |
| Широкий десктоп / 4K | 2560 × 1440 | контент не растягивается, фоны и сетки не «кончаются» |

- **Ничего не считать от ширины экрана без ограничения.** Размер элемента — в dp с пределами (`coerceIn`), количество — от ширины
  (как колонки стены на входе). Ошибка «3 колонки на всю ширину → обложки по 500 dp» — ровно отсюда.
- Списки и текст — `Modifier.readableWidth()` (по центру, не шире 760 dp); крупные заголовки — подбор кегля по ширине (`fitArtistName`).
- Фоны и бесконечные анимации закрывают окно любого размера с запасом (поворот, масштаб) и крутятся бесшовно.
- **Тест на матрице** в том же изменении: логика раскладки проверяется на размерах из таблицы (пример — `ArtistWallTest`,
  `ArtistNameFitTest`). Визуально — симулятор iPhone SE и iPad (портрет и альбом) + десктопное приложение.

### Бренд
- Фон `#0B1220`, панели `#121B2C`, акцент `#5EE6A8`, текст `#E6EEFC`, второстепенный `#9AB0D5`.
- Системный крупный шрифт учитываем до ×1.2 (`MAX_FONT_SCALE` в `DJMetryApp`): iOS Dynamic Type на iPhone с крупным шрифтом (~×1.45) разваливал капсулы и плитки. Вёрстку проверяем при ×1.3 — с запасом.
- Обложки и фото — `CoverImage` (скругление, рамка, тень, блик). Логотип — только `DJMetryLogo`.
- **Никаких эмодзи** — ни в интерфейсе, ни в текстах. Только иконки Material (`Icons.*`) или свои векторные: страна — `Public`, жанр — `MusicNote`, поиск — `Search`, выбор — `Check`, удалить — `Close`. Флаги стран — картинками `CountryFlag` (flagcdn, как на сайте). Сторож — тест `NoEmojiTest`.
- Тексты — на 12 языков сразу.

## 3а. Архитектура (как расширяться)

Слои: **экран (Compose) → ViewModel → репозиторий → API**. Экран только рисует состояние и передаёт действия.

- **Состояние экрана — во ViewModel**, не в `remember` экрана: тогда оно переживает смену вкладки, поворот, смену темы и шрифта. ViewModel берётся через `appViewModel<MyViewModel>()` (`ui/search/AppViewModel.kt`): хранилище ViewModel — у `AppContainer`, очищается при выходе из аккаунта. Несколько экземпляров одного класса — `appViewModel<…>(key = id)`.
- **Зависимости — через Koin** (`di/AppModule.kt`, изолированный граф у каждого `AppContainer` — тесты не делят состояние). Новый репозиторий или ViewModel объявляется **только** в `appModule` (`single { … }`, ViewModel — `factory { … }`) и получает зависимости через `get()`. Старые репозитории пока живут в `AppContainer` и отдаются в Koin как есть; экран, переехавший на ViewModel, больше не берёт `LocalAppContainer`.
- **Данные пользователя** (всё, что нельзя показать следующему аккаунту) — репозиторий реализует `UserScoped` и добавляется в `AppContainer.userScoped()`.
- **Обычные настройки на устройстве** — `SessionStorage.getPref/setPref` (не секреты; секреты — только в защищённом хранилище).
- **Поиск**: любой новый поиск получает свой `SearchScope` (`data/search/SearchHistory.kt`) — история появляется сама: поле-фильтр — `SearchField(…, history = …)`, выбор из списка — `SearchPickerDialog(history = …)`, полноэкранный — `SearchHistoryPanel`. Ключ `SearchScope` хранится на устройстве — не переименовывать.
- **Сеть** — Ktor 3; запросы только в `api/endpoints`, экраны в API не ходят.
- Все экраны с состоянием — на ViewModel (поиск, «Открытия», Радар, Букинг, Рейтинг, карточка, «Все релизы», профиль, карта, аналитика, аудитория). Новый экран: класс `…ViewModel` рядом с экраном, `factory { … }` в `appModule`, в экране `appViewModel<…>()` и `var x by vm::x`; загрузки — с проверкой «уже загружено», чтобы возврат на экран не повторял запросы. Мелкие поля форм и выбранная страница — `rememberScreenState(экран, ключ, исходные данные) { … }`. Тест — в `ViewModelScopeTest`.

## 4. Тесты

**Всё покрывается тестами. Без зелёных тестов приложение не выходит в продакшен.**
Тесты пишутся в том же изменении, что и код. Код проектируется тестируемым: HTTP-движок, браузер входа и хранилище
передаются снаружи (`createApiClient(engine = …)`, `AuthRepository(redirect = …)`, `SessionStorage`).

```bash
./gradlew :shared:testAndroidHostTest
```

```bash
./gradlew :shared:iosSimulatorArm64Test
```

```bash
./gradlew :shared:desktopTest
```

Общие тесты (`shared/src/commonTest`) выполняются на всех платформах, десктопные — в `shared/src/desktopTest`.

### Как писать тесты

- Сеть — через `FakeBackend` из `commonTest/.../TestSupport.kt`: маршрут `"GET /api/..."` → статус и JSON.
  Он же записывает запросы, чтобы проверить заголовки, параметры и тело.
- Хранилище — `FakeSessionStorage`.
- Браузер OAuth — лямбда, которая возвращает deep-link (`djmetry://oauth?code=…` или `?error=…`) или бросает `OAuthCancelledException`.
- Новые строки интерфейса добавляйте в `TranslationsTest.requiredKeys` — тест не даст забыть перевод.

## 5. Платформы и запуск

| Платформа | Модуль | Запуск |
|---|---|---|
| Android | `androidApp` | `./gradlew :androidApp:assembleDebug` |
| iOS / iPadOS | `iosApp/DJMetryApp` (Xcode, собирает `shared` сам) | Xcode, минимум iOS 16 |
| Десктоп macOS / Windows / Linux | `desktopApp` | `./gradlew :desktopApp:run`, установщики `packageDmg` / `packageMsi` / `packageDeb` |

- Стек: Kotlin 2.4.20, Compose Multiplatform 1.12.1, Gradle 9.8, AGP 9.4.1, compileSdk 37. JVM-часть собирается JDK 25
  (toolchain, Gradle скачает сам): MapLibre на десктопе работает только на Java 25, установщики упаковываются с ней.
- Графики — Vico (`com.patrykandpatrick.vico:multiplatform`), карта — MapLibre Compose (`org.maplibre.compose`,
  тайлы OpenFreeMap без ключей; атрибуция OpenStreetMap обязательна). В тестах и превью карта — заглушка (`LocalInspectionMode`).

- Память Gradle задана в `gradle.properties` (4 ГБ).
- Симуляторы iOS 26 на рабочем Mac ломают WebKit — проверять на iOS 18.x или на устройстве.
- Установщики Windows/Linux собираются на своих ОС; для раздачи macOS-сборку нужно подписать и нотаризовать.

### Вход на всех платформах
Только OAuth: Apple, Google, Facebook. PKCE → одноразовый код → Bearer-токен (детали — BACKEND_API.md).
Способ получить редирект — стратегия `OAuthRedirect`: телефоны — `djmetry://oauth`.

### Вход на десктопе

Общий контракт — `OAuthRedirect` в `shared/.../auth/OAuthRedirect.kt`. `AuthRepository` не знает, какая
платформа: стратегия сама выбирает `app_redirect`, открывает браузер и возвращает редирект с кодом.
Дальше — общий флоу: PKCE → `/api/auth/mobile/token` → Bearer.

| Стратегия | `app_redirect` | Когда | Бэкенд |
|---|---|---|---|
| `DesktopSchemeRedirect` | `djmetry://oauth` | установленное приложение (`.dmg` / `.msi` / `.deb`) | работает сейчас |
| `LoopbackRedirect` | `http://127.0.0.1:<порт>/oauth` | запуск из исходников (`:desktopApp:run`) | нужна доработка — [BACKEND_API.md → Задача для бэкенда: loopback](BACKEND_API.md#задача-для-бэкенда-loopback-для-десктопа) |

Выбор — `chooseDesktopRedirect()`:
- установленное приложение (jpackage выставляет `jpackage.app-path`) → схема;
- запуск из исходников → loopback (схема в этом режиме в ОС не зарегистрирована);
- переопределение: переменная окружения `DJMETRY_OAUTH_REDIRECT=scheme|loopback`.

#### Схема `djmetry://`
- **macOS** — `CFBundleURLTypes` в Info.plist (`desktopApp/build.gradle.kts`). Ссылка приходит в работающий
  процесс через `Desktop.setOpenURIHandler`.
- **Windows** — при запуске установленного приложения пишем `HKCU\Software\Classes\djmetry`
  (без прав администратора, путь к exe обновляется после апдейта). ОС открывает ссылку новым процессом —
  он пересылает её первому окну через локальный сокет (`SingleInstance`) и закрывается.
- **Linux** — `~/.local/share/applications/djmetry-url.desktop` + `xdg-mime default`; дальше как на Windows.

#### Loopback (RFC 8252 §7.3)
Сервер на `127.0.0.1` со случайным портом, путь `/oauth`, живёт до первого запроса или 5 минут.
После возврата браузер показывает страницу «Готово — вернитесь в DJMetry».

### Хранение данных на десктопе
- Токен — системное хранилище секретов (`java-keyring`): Keychain, Credential Manager, Secret Service.
  Если его нет — токен только в памяти, на диск в открытом виде не пишется.
- Язык и флаг онбординга — `java.util.prefs`.
- Одна копия приложения — lock-файл и порт в `~/.djmetry/`.

## 6. Ассеты
- Дизайн-исходники — `design/` (см. `design/README.md`). Полная копия `public/` сайта — только локально, в git не идёт.
- Иконки всех платформ пересобираются из `design/icons/generate_icons.swift`.

## 7. Git
- Коммиты — в отдельной ветке, не в `main`. Дампы памяти (`*.hprof`), `build/`, `xcuserdata` — в `.gitignore`.
- **После каждой выполненной задачи — сразу коммит** (тесты зелёные, журнал обновлён). Сообщение — по-русски. Push делает владелец репозитория.
